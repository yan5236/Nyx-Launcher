# 界面与功能说明

使用 C#、.NET 10 和 WinUI 3 重新构建的 Windows 启动器。

当前已接入真实 Java 游戏版本清单，包含首页、版本管理、下载，以及从左下角账户弹层进入的账户和设置页。使用原生 WinUI 3 控件，不包含 WebView。

侧栏仅放导航与底部头像、用户名，不显示应用图标或应用名。界面使用浅色主题，正文 15、导航 16；各页面不再显示页面标题，减少副标题和描述性文本。账户菜单从上到下为“账户”、分隔线、“设置”。

下载页顶部为“游戏、模组、整合包、资源包、数据包、光影”六个分类 Tab。游戏分类从 Mojang / BMCLAPI 获取真实版本，搜索框即时过滤本地清单，类型默认正式版，提供全部类型、正式版、快照版、远古版和愚人节版。滚动条位于卡片外侧的右边留白，卡片与搜索栏保持对齐。需要分页的资源分类将上一页、页码和下一页放在筛选项右侧，与筛选框底部对齐；列表下方不再保留分页行。游戏与资源列表使用剩余高度，主内容区各页面不预留底部内边距。

其余五类资源使用 [Modrinth v2 官方搜索](https://docs.modrinth.com/api/operations/searchprojects/)，不再使用演示数据。独立“搜索”按钮或 Enter 提交关键词，下方为 Minecraft 版本、加载器（仅模组）、类型、来源筛选；筛选变更立即查询第一页，翻页保留已提交关键词。版本项和类型项从平台获取，按当前资源分类提供中文类型，数据包复用平台的模组类型；版本下拉只列正式版，排除快照、远古及愚人节版本，同时可手动输入版本 ID，按 Enter 或离开输入框后应用，手动值不写入下拉列表。加载器及平台保留正式名称。来源提供“全部”、Modrinth 和禁用的“CurseForge（暂不可用）”，当前全部来源仅查询 Modrinth。资源卡片左侧显示无背景、无边框的真实图标（模组、整合包、资源包、数据包、光影分别使用拼图、箱子、图片、数据文件和太阳作为加载中或失败时的透明占位），右侧依次为名称、平台简介，以及带图标的下载量、模组加载器、支持版本、来源和更新日期，信息行随宽度换行，完整简介和版本可悬停查看。Quilt 标签使用项目内 quilt.svg，仅用于资源展示，不增加 Quilt 安装或运行支持。图标用 SkiaSharp 4.154.0 解码 WebP 等格式并保留透明通道，最多 4 路下载、单图 4 MiB/4096 像素限制、15 秒超时、失败重试一次，并缓存最多 128 张最长 128 像素的 PNG；卡片卸载取消请求，不再从迟到的图片事件访问父控件。卡片版本按系列压缩，同系列补丁合并，连续覆盖到平台最新正式版时显示如“1.16+”，历史范围显示如“1.12–1.15”，断开的系列单列；悬停保留完整版本 ID。每页 20 项，支持上一页和下一页。加载时居中转圈，失败转为叉号、中文错误提示和重试；离开页面或更改筛选会取消旧请求。模组卡片现可进入[真实模组下载详情](mod-downloads.md)；其余资源类别暂只提供发现与筛选，尚不导入整合包或写入资源文件。

首页读取当前游戏目录中的真实版本，使用用户添加并选中的离线、微软或外置账户启动。默认账户为空；账户页支持原生弹窗添加和点击卡片切换，侧栏、首页及实际游戏身份同步。启动会检查并补齐资源与依赖、完成对应账户认证并等待真实游戏窗口，按钮依次显示红色“停止”和“停止运行”。微软登录使用系统浏览器，支持重新授权、静默刷新和 Windows 用户加密缓存；客户端配置见[微软登录](microsoft-login.md)。外置登录支持 LittleSkin 和兼容 Yggdrasil 的皮肤站，包含服务器编辑／删除、卡片拖入、账号密码登录、头像选角和加密会话缓存，详见[外置登录](external-login.md)。文件下载、原版及 Forge / Fabric / NeoForge 安装已接入，详见[账户、头像与启动生命周期](accounts-and-launch.md)。

## 下载任务

下载页右侧独立“下载任务”Tab 显示任务列表，与左侧内容分类分开。安装配置页成功创建任务后立即返回原列表，任务 Tab 右上角亮起 Badge，进入任务页清除。离开下载模块不会停止后台任务。

任务页右上角提供状态筛选和“创建下载”。弹窗依次填写 HTTP(S) 下载链接、通过原生选择器选择下载目录；右下角为“取消”和深色“下载”。文件名取 URL 路径最后一段，同名目标、路径穿越和 Windows 保留名称会明确拒绝，不覆盖已有文件。

任务卡片显示真实阶段和进度，右侧为打开目录、暂停/继续、取消图标，提供悬停提示及无障碍名称。完成或取消清理结束后，取消图标变为删除，**只移除任务记录，保留磁盘文件与共享游戏资源**。正在取消时需等待清理结束。状态变化通过属性通知更新原卡片，不重新绑定整个列表或重播入场动画。

游戏下载并行处理依赖文件；普通大文件在服务端支持 Range 且有强 ETag 时最多使用 4 个分段，响应范围错误自动退回单连接。文件与游戏任务共用连接数、限速和有限重试。下载先写随机临时文件，验证长度及上游 SHA-1 后才发布；合法空文件可按哈希验证。暂停中断本轮请求和安装处理器，继续复用完整游戏文件，未完成的单文件会重新下载。任务记录保留在本次应用会话中，退出时先禁用页面操作并拒绝新建或恢复任务，再取消已有任务并等待清理，暂不提供跨重启续传。

游戏安装复用 [CmlLib.Core](https://github.com/CmlLib/CmlLib.Core) 4.1.0 和 [Forge 安装器](https://github.com/CmlLib/CmlLib.Core.Installer.Forge) 2.0.0。下载实际客户端、assets、libraries 和 Java；Fabric 使用所选版本的真实 profile，Forge / NeoForge 执行安装包中的客户端处理器。任务先写入当前目录的 `.nyx-install/<任务 ID>`，完整安装后将独立清单和客户端发布到 `versions/<自定义名称>`，版本管理和首页随即刷新。同一个游戏目录的安装任务排队保护共享处理器输出，各任务内部的文件下载仍然并行；普通文件任务可同时进行。失败或取消不发布半成品，不覆盖已存在版本。

通用设置的“版本隔离”提供关闭、隔离可安装 Mod 的版本、隔离非正式版、两者均隔离、隔离所有版本（默认）。以实际清单的加载器及版本类型判断，启动时同时设置 `--gameDir` 和进程工作目录；隔离目录为该版本目录，关闭则使用游戏根目录，assets/libraries/runtime 继续共享。更改策略不搬移、合并或删除已有存档。

首页手动选择版本后立即在 `game-folders.json` 中按游戏目录保存，无需先启动游戏；下次打开或切回该目录时恢复选择。没有历史选择、原版本已删除或清单损坏时回退首个有效版本，无有效版本时留空。刷新列表不覆盖历史选择，保存失败在首页提示。

## 本地版本管理

顶部左侧为无边框的游戏目录按钮，显示当前路径并支持悬停查看全文；右侧“安装新版本”跳转下载页的游戏分类。其下为搜索栏和真实版本卡片，支持按名称、游戏版本及加载器信息搜索。卡片左侧为图标，右侧分两行显示目录名称和版本信息，行尾为独立 SVG 删除按钮。点击卡片直接进入该版本详情，顶部显示版本图标、名称与游戏/加载器信息，提供“基础 / 模组管理 / 游戏设置 / 导出”四个 Tab，游戏设置提供版本独立的内存分配，模组管理与导出暂时留空。基础页可编辑版本名，点击“保存”或按 Enter 后同步更改目录、同名 JSON/JAR 及清单标识，保留存档、模组、图标和其他文件；非法名称、同名冲突、坏清单、链接和仍被其他版本继承或引用 JAR 的基础版本会拒绝改名，普通 I/O 失败尝试回滚。游戏启动/运行或游戏、模组安装任务执行及清理期间禁止改名和删除。列表进入详情时向左淡出，详情从右侧淡入；返回时反向播放，时长 220 毫秒，遵循系统动画开关。转场期间防止重复触发，离开版本管理时停止动画并恢复列表。返回保留搜索条件。基础页底部提供“危险区”，点击“删除版本”复用列表行尾删除按钮的确认对话框；取消保留详情，成功移入回收站后返回并刷新列表。

“修改”图标使用原生文件选择器，支持 PNG/JPEG/BMP（输入不超过 16 MiB、边长不超过 4096），解码缩小为最长 256 像素 PNG，原子保存为版本目录中的 `.nyx-icon.png`，详情、版本列表与首页共用；源图片移动不影响已保存图标。损坏或缺失图标回退默认游戏图标。四个带图标的“快速打开”按钮一次点击用资源管理器打开版本、模组、存档或截图文件夹；版本目录固定指向该版本，后三项遵循当前版本隔离设置，不存在的子目录首次点击时创建。

启动器启动时在程序所在目录（EXE 所在目录，不是终端工作目录）创建 .minecraft。首次使用将其登记为默认游戏目录；添加的目录和当前选择保存到 %LOCALAPPDATA%/NyxLauncher/game-folders.json，采用临时文件替换，重启恢复。若默认目录已从列表移除，后续启动仍确保磁盘目录存在，但不会强行重新登记。

点击路径打开“选择文件夹”弹窗：右上角关闭，底部“添加文件夹”调用真实系统文件夹选择器，添加成功后留在列表中；点击路径成功保存选择后立即关闭。行尾 SVG **只移除列表记录，不删除磁盘文件**，移除时弹窗保持打开；移除当前项会切换到剩余首项，全部移除则显示空状态。路径不可访问或保存失败明确报错，不伪装成功；损坏配置保留原文件并禁止覆盖。

版本来自所选目录下 `versions/<名称>/<名称>.json`，读取原版、Forge、Fabric、NeoForge 的本地信息与继承关系，不代表文件完整性或游戏可启动性已验证。单个坏清单保留在列表并显示错误，缺失父版本、循环、越界继承和超过 8 MiB 的清单不会被当作有效信息。

删除版本需要确认，目标为单个版本目录并使用系统回收站，包含该版本目录内的独立存档、模组和设置；不会删除共享资源或游戏根目录。删除前重新校验路径，拒绝目录/文件链接及仍被其他版本继承的基础版本，错误留在页面。详情暂不提供启动参数编辑或模组编辑。

## 游戏安装配置页

点击下载页“游戏”分类中的版本条目进入安装配置页。顶部可编辑版本名称，右侧深绿色“安装”按钮创建后台任务并立即返回列表，错误则留在页面提示。下方依次显示 Forge、Fabric、NeoForge，每个加载器的 32×32 本地图标、名称、同一行灰色状态和右箭头合并在同一张卡片中；卡片最小高度为 56，间距为 10。可用行点击后弹出“选择加载器版本”列表，左侧是加载器图标，主标题为版本号；Forge 副标题为发布日期，Fabric 与 NeoForge 为“稳定版 / 测试版”。列表按版本号自然降序排列并去重，可滚动；点选后立即关闭，原行显示“已选择 + 版本号”，右箭头变为叉，其他加载器置灰且不可选择。点击已选行的叉取消后恢复其他行。右上角叉或 Esc 仅关闭弹窗，不选择；使用 WinUI ContentDialog 原生开关动画与模态焦点，遵循系统动画设置。创建任务时锁定名称、当前游戏目录和加载器版本；切换游戏清空尚未提交的选择。

进入时列表向左淡出，配置页从右侧淡入；返回时反向播放，时长 220 毫秒。转场期间防止重复触发；关闭系统动画后直接切换。返回保留搜索、筛选和滚动位置，离开下载模块时取消转场与探测。

三个加载器独立拉取真实版本列表，状态为“正在检测… / 可以添加 / 暂无可用版本 / 检测失败”。悬停失败状态可查看原因，页面不再提供重新检测按钮；返回列表后重新进入会再次探测。探测始终使用所选游戏的原始 ID，不受版本名称编辑影响：

- Forge：读取 [官方 Maven 清单](https://maven.minecraftforge.net/net/minecraftforge/forge/maven-metadata.xml)，精确匹配游戏版本前缀及后续构建号；日期来自官方游戏下载版本页。镜像使用 BMCLAPI `/forge/minecraft/{游戏版本}` 的版本、分支与 `modified` 日期。官方日期缺失或页面结构变化会触发镜像回退，不编造日期。
- Fabric：先读取 [Meta 游戏支持列表](https://meta.fabricmc.net/v2/versions/game)，再查询对应游戏的 loader 列表，避免将旧版不支持导致的 HTTP 400 当成网络失败。新版去混淆游戏（例如 26.3）的 `intermediary.version` 为通用映射 `0.0.0`，不是游戏 ID；解析接受这个占位值，仍由官方支持清单及具体游戏的 loader 请求限定支持范围。
- NeoForge：读取 [官方 Maven 清单](https://maven.neoforged.net/releases/net/neoforged/neoforge/maven-metadata.xml)，按[官方编号规则](https://github.com/neoforged/documentation/blob/main/docs/gettingstarted/versioning.md)匹配 1.20.2 以后版本、26.x 及快照；1.20.1 使用 `net.neoforged:forge` 的历史清单。

加载器列表与可用状态共用同一次真实清单结果，遵循设置中的“版本列表源”：镜像优先 / 官方缓慢 3 秒后并发镜像 / 官方优先；失败回退，成功后取消另一源。Fabric 使用 BMCLAPI `/fabric-meta/v2/versions/...`，NeoForge 使用 `/maven/net/neoforged/{forge,neoforge}/maven-metadata.xml` 透传端点，映射见 [BMCLAPI 官方文档](https://bmclapidoc.bangbang93.com/)。Fabric 稳定性读取 `loader.stable`，NeoForge 根据构建号的预发布标记区分。每个加载器单源总超时 15 秒、单响应上限 8 MiB，失败不伪装为“不支持”；返回或离开页面取消旧请求。保留系统代理与 HTTPS 校验，不写磁盘缓存。

## 版本列表与下载设置

游戏下载详情页支持选配 Fabric API：选择 Fabric Loader 后可选择与原始游戏版本匹配的 API 发布，随安装任务下载并校验到实际隔离/共享游戏目录的 `mods` 中。来源、冲突保护和验证记录见 [Fabric API 下载](fabric-api.md)。

设置页沿用下载页的 SelectorBar，分“通用 / 启动 / Java / 下载”。Java 管理详见 [Java 管理与安装](java-management.md)。下载设置不提供统一目标文件夹选项；文件下载源和版本列表源可分别选择：

- 尽量使用镜像源：先尝试 BMCLAPI，失败再尝试官方。
- 优先使用官方源，在加载缓慢时换用镜像源：官方超过 3 秒时同时请求镜像，使用首先返回的有效清单；官方提前失败则立即尝试镜像。
- 尽量使用官方源：先尝试官方，失败再尝试镜像。

单源请求含正文读取最多等待 15 秒；正文上限为 8 MiB；空清单、无效 JSON、HTTP 错误和超时均触发回退。成功后取消剩余请求。保留 HTTPS 证书校验，不提供关闭选项。镜像映射依据 [BMCLAPI 文档](https://bmclapidoc.bangbang93.com/)。

打开游戏分类时显示旋转圆弧及“正在加载版本”，成功后淡出状态并淡入列表；双源失败时圆弧先变红，再过渡成交叉，显示错误原因与重试。离开页面或切换分类会取消旧请求，避免旧结果覆盖新页面。

设置 → 下载分组新增“并行下载文件数”滑块，范围 1–64（默认 16），保存后重启保留。普通文件与 Minecraft 的 assets、libraries、Java 等资源共用此文件上限；设置为 1 时串行，较大值允许多个资源同时下载。设置页的最大下载线程数仍为 1–64（默认 16），限制总连接数（含大文件分段）；速率滑块为 0–100 MiB/s（0 表示不限速）。这些限制在下一批任务开始、或没有其他活跃任务时继续下载后生效，活跃批次沿用原限制。版本清单请求使用独立的版本列表源策略。实际文件的混合源策略在官方响应头超过 3 秒时切换镜像，不并行下载两份正文；任意自定义链接不会改写为镜像。正文使用 30 秒空闲超时，持续传输的大文件不受总时长限制。

下载和隔离设置保存到 `%LOCALAPPDATA%/NyxLauncher/download-settings.json`，采用同目录临时文件替换；读取损坏或写入失败会显示错误。浏览版本列表不写磁盘缓存；安装阶段在任务暂存目录保存安装清单。

愚人节版本使用独立精确 ID 清单，不按四月一日日期猜测，见 [维护列表与来源](april-fools-versions.md)。

## 启动内存设置

设置分类依次为“通用 / 启动 / Java / 下载”。启动页提供全局内存分配；版本管理 → 版本详情 → 游戏设置提供同款卡片及“恢复全局设置”。默认自动分配，自动时滑块禁用；手动滑块以 256 MiB 为步进，范围从 512 MiB 到物理总内存，允许超过当前可用内存，此时分配数值后显示“（可用 X GB）”。占用条分别显示系统已用、游戏分配可容纳部分与剩余空间，文字保留完整分配值。

所有版本默认跟随全局。局部修改保存完整独立偏好，后续全局修改不覆盖它；恢复按钮只删除当前版本覆盖。全局配置为 `%LOCALAPPDATA%/NyxLauncher/launch-memory.json`，版本覆盖为版本目录内 `nyx-memory.json`，随版本改名和删除，不受游戏隔离策略影响。损坏配置与写入失败明确报错，不覆盖原值。

可见卡片每 500 毫秒通过原生系统查询刷新内存数值与占用条，显示两位小数；离开页面或卸载后停止采样。相同快照跳过绘制，文字未变不重新赋值，定时刷新不触碰手动滑块或写入配置。偏好仅在进入页面或用户修改时读取，模组数量在进入页面时统计，启动时仍重新统计；预览期间外部修改配置或模组需重新打开页面。全局预览使用首页当前版本，卡片不显示描述性副标题。自动分配以旧版（1.17 之前）2 GiB、现代或未知版本 3 GiB 为基础，加载器加 1 GiB，每个启用 jar 模组加 32 MiB（最多计 1024 个），按实际隔离/共享 mods 目录统计。预算不超过物理内存的 75%，并从可用内存中预留至少 1 GiB 或总量的 10%；最终按 256 MiB 对齐、最低 512 MiB。此为启发式估算，极低空闲量时最低值仍可能超过可用量。

实际构造启动进程时重新读取偏好、实时内存与模组数量，将结果传入 JVM 最大堆参数；不修改正在运行的游戏。手动值不因空闲量下降而缩小，物理总量改变时按新总量限制实际值。Java 堆外内存仍会额外占用系统资源。
