# 界面与功能

## 当前能力

| 入口 | 已实现 | 边界 |
| --- | --- | --- |
| 首页 | 选择本地版本、账户启动、阶段反馈、停止与故障日志 | 发现窗口不代表世界已加载完成 |
| 服务器 | 自定义和精选服务器、进入页面自动查询状态、选择本地实例并直连 | 精选项可改名和设置默认版本 |
| 联机 | 房主和访客入口、邀请码及玩家列表 | 陶瓦自动共享它发现的首个世界，一次只能开房或加入一个房间 |
| 版本管理 | 目录登记、扫描、搜索、改名、图标、回收站删除、整合包导入、模组管理 | 导出 Tab 仍为空 |
| 下载 → 游戏 | 原版及 Fabric / Forge / NeoForge 安装、可选 Fabric API | 不提供 Quilt 安装 |
| 下载 → 模组 | 搜索、三级详情、必需前置跳转、安装或指定目录下载 | 不自动解析、安装或升级整套依赖 |
| 下载 → 资源包 / 数据包 / 光影 | 选择兼容发布、安装到版本或存档、指定目录下载 | 不自动启用，不安装光影加载器 |
| 下载 → 整合包 | 在线安装及本地 Modrinth / MCBBS / MultiMC 导入 | 具体限制见[整合包安装](modpack-installation.md) |
| 本地拖入 | 识别 JAR / ZIP / MRPACK 并确认安装目标 | 不完整解析本地资源游戏版本范围及依赖 |
| 账户与设置 | 离线、微软、外置账户；隔离、内存、高级启动、Java、下载偏好 | 微软入口需要有效的构建配置 |

资源目录当前查询 Modrinth，CurseForge 搜索不可用。“全部来源”不代表已接入多个平台。下载任务不支持跨重启恢复。

首页是一张世界画面加悬浮控制台：左侧是游戏版本选择器，右侧是版本管理与启动/停止按钮，控件尺寸固定，窗口缩放只改变画面大小；启动阶段文案、百分比和进度条在启动时代替选择器出现，结束后交还，不额外占用首屏空间。首页不显示账户、Java、游戏目录等与启动无关的信息。

## 页面交互

主导航及账户菜单之间切页时，内容区域以 220 毫秒淡入并从下方 16 像素缓出归位；侧栏、标题栏和崩溃提示保持稳定。快速连续切页立即响应最后一次选择，不排队等待动画；重复进入当前页不重播。系统关闭动画时直接显示，页面按需创建及后台任务生命周期保持原有规则。

下载分类与下载任务、设置、版本详情、衣柜的 Tab 正文也使用相同转场；标签栏、页面标题、提示和衣柜左侧模型不参与动画。切换立即更新分类并执行原有的请求取消与加载逻辑，动画不等待网络结果，也不延迟点击。

侧栏提供首页、版本管理、下载、衣柜、服务器、联机及底部账户入口，窗口标题栏左上角按钮可展开或收起侧栏，收起时保留导航图标和居中的账户入口，账户菜单向右展开并限制在应用窗口内，始终使用不透明的当前主题底色，不受背景图片或侧栏透明度影响；账户菜单只提供账户和设置入口，关于仅位于设置 Tab 中。支持跟随系统、浅色和深色原生控件，保留红色停止语义，不增加重复标题与描述性副标题。转场遵循系统动画开关，离开页面时取消加载并丢弃迟到结果。

设置 → 关于使用原生 ScrollView 纵向滚动；静态清单关闭自动滚动锚定，键盘聚焦链接仍会将其滚入可见区域。首次打开时创建，显示应用图标、名称及当前程序集的产品版本；检查更新打开弹窗，比较 GitHub 最新正式版并显示更新说明，确认后创建共享下载任务，沿用暂停、重试、取消和限速。单文件发布版下载、校验后替换磁盘 EXE，当前窗口继续使用，下次启动生效；默认不自动检查或更新。目录/开发构建提示手动下载，打包与替换边界见[开发指南](development.md#协议与自身更新)。GitHub、[官方网站](https://nyxlauncher.nanhaiblog.top/)、用户协议与隐私协议均在系统浏览器打开，协议直接指向仓库根目录的对应文件，失败在页内提示。

首次使用或协议修订变化时，主窗口先提示阅读两份协议，必须主动勾选并同意，且本地确认保存成功后才创建主页面和账户/下载服务；拒绝或关闭弹窗退出。

设置 → 通用 → 外观提供独立的“首页图片”更换、移除及恢复默认按钮。自选图片验证格式、大小及像素上限后保存本地副本，立即更新首页；移除同时隐藏图片暗角和遮罩，保留版本选择、启动及进度功能，不影响整个窗口的背景图片。

关于页的[第三方清单](../src/NyxLauncher/Assets/ThirdPartyNotices.json)按上游项目归并直接、间接 NuGet 包，另列原生 Skia、自包含 .NET 运行时、随附 Java 兼容组件及按需下载的 authlib-injector，提供项目和许可链接；微软专用分发条款单独标识。清单不代表用户另行安装的 Minecraft、Java、加载器或模组的完整依赖清单。升级依赖时同步维护条目和版本，并运行结构检查核对还原图。

游戏搜索过滤已加载清单；其他资源通过搜索按钮或 Enter 提交，筛选改变回到第一页。资源详情返回保留目录的搜索、筛选、页码与滚动位置。版本筛选可手动输入，平台标签与卡片摘要不作为安装兼容性的唯一依据。详见[模组与资源](mod-downloads.md)。

## 服务器

侧栏「服务器」提供「服务器」与「精选服务器」两个标签。自定义服务器在窗口内容上层打开的表单中填写名称和 Java 版服务器地址，可从已登记游戏目录选择默认启动实例；打开表单时遮罩覆盖侧栏和页面内容，标题栏保持可操作。卡片菜单可修改或删除自定义服务器。删除确认显示名称、地址和影响，默认取消；确认后只移除本机列表记录。精选地址来自内置 [JSON 清单](../src/NyxLauncher/Assets/FeaturedServers.json)，只可修改本地显示名称和默认启动版本。自定义列表为空时，列表区域居中显示服务器图标、「暂时没有服务器呢，点击右上角或下方添加」和打开同一添加表单的按钮；精选页始终使用清单，不显示这个空状态。

启动版本使用卡片弹窗。打开时沿用版本管理当前选中的游戏目录，只显示该目录下的版本；没有选中目录时可在弹窗中先选。弹窗内切换目录只更新本次的版本列表。每张卡片显示实例图标、版本名和「Minecraft 1.21.4 · Fabric: 0.16.9」这类副标题小字，已绑定的实例带「默认」标记。单击卡片立即选用并关闭，不再叠加一次确认。添加或修改表单时可留空或清除默认版本。版本行显示当前实例及其副标题，点击后打开同一卡片弹窗更换。

点击「启动」使用仍可用的默认实例并回到首页显示进度。没有有效默认实例时直接打开版本卡片弹窗。点击启动按钮右侧的箭头可为本次启动打开同一弹窗，选择后立即启动。临时选择不会更改服务器默认版本或首页版本选择。

首次打开自定义或精选列表时，从本机直接发起 Java 版状态探测。之后打开列表直接显示本次运行的缓存，只补查尚未完成的地址。添加服务器或修改地址后自动查询该地址，已有其他查询时可并发进行；点击刷新则重新查询当前列表全部地址。默认端口的域名先查 SRV，最多等待两秒；查询超时或没有可用记录时尝试原地址，连接与状态读取另有六秒预算。各卡片在自己的探测完成后立即更新。卡片显示服务器提供的彩色简介（MOTD）、版本、玩家数、图标及 Ping 延迟，宽窗口按卡片宽度给版本留出完整文本，较长版本不在数字列被截断。切换标签或离开页面会取消未完成的查询，已取得的结果保留到本次运行结束。

## 联机

侧栏「联机」由 [Terracotta 陶瓦联机](https://github.com/burningtnt/Terracotta)和 [EasyTier](https://github.com/EasyTier/EasyTier)提供支持。首次进入联机页且缺少模块时会提示下载。设置 → 通用 → 联机模块可下载并校验 Windows x64 陶瓦 v0.4.2、选择已解包的兼容 EXE，以及将当前或最近一次陶瓦日志导出为 `.log` 文件。启动器会记住所选路径，每次运行需手动启用模块。

启用后从首页启动 Minecraft Java 版。房主在游戏中对局域网开放世界，再选择「我是房主」。房间详情显示陶瓦报告的玩家列表和邀请码。访客选择「我是访客」，在弹窗输入邀请码，连接成功后将直连地址粘贴到游戏的「多人游戏 → 直接连接」。详情左上角返回联机首页，进行中的房间可以从模块开关上方的提示重新进入。房主通过详情右上角关闭房间，访客可退出联机。切换启动器页面可继续联机，退出游戏后结束房间，退出启动器会停止陶瓦进程。

设置 → 通用 → 外观的「主题色」下拉框收起时，滚轮用于滚动页面。通过展开选项或键盘操作可切换主题色。

## 页面内存与后台活动

侧栏衣柜提供微软账户皮肤与披风预览和应用，布局为左侧账户及模型、右侧搜索和分类卡片；加载时在右侧列表区域中央显示转圈及“正在加载…”，结束后恢复列表。切换分类清除旧选择并恢复当前穿戴组合，皮肤和披风卡片分别用于对应纹理。上传皮肤仅保存本机副本，操作范围见[衣柜](accounts-and-launch.md#衣柜)。

启动只创建首页与共享业务状态。下载、版本管理、衣柜、账户和设置首次进入时才创建，联机状态在首次进入联机或设置时初始化。游戏安装、模组和版本详情也按需创建，自定义颜色编辑器仅在自定义配色时创建。

通过侧栏离开下载或版本管理时，取消页面请求并释放结果列表、详情文件与依赖返回历史；返回原模块重新加载，筛选条件仍保留。在详情内部返回依赖来源仍保留原阶段与文件列表。已创建的下载任务独立运行。

窗口失焦时暂停内存预览采样和背景文字对比取样，重新聚焦恢复；持续失焦五秒后卸载下载模块的隐藏详情，并最多每分钟主动回收一次不可达托管对象，下载、启动或导入忙碌时跳过。版本设置详情保持单实例复用；下载详情在前台频繁切换时也复用控件，避免反复创建原生模板。不会裁剪进程工作集。运行库、字体、图像和系统控件缓存仍可能保留，因此返回首页不保证恢复到冷启动内存。

## 版本与目录

启动器在 EXE 所在目录创建默认 `.minecraft`；目录登记和各目录所选版本保存在用户配置中。移除目录登记不删除磁盘文件，已移除的默认目录不会被强行重新登记。扫描读取本地版本与继承关系，坏清单保留错误提示；列表出现版本不代表完整性检查通过。

版本详情提供基础、模组管理、游戏设置、导出四个 Tab。基础页可同步改名目录、同名清单/JAR 与标识，保存自定义图标，并打开版本、模组、存档和截图目录。非法名称、冲突、链接、坏清单及被其他版本依赖的基础版本会拒绝改名。删除需确认并将单个版本目录移入回收站，其中独立存档和模组也会移走，不删除共享资源。游戏启动/运行及相关安装任务执行、收尾期间阻止改名和删除。

隔离可关闭，或按模组版本、非正式版、两者、所有版本选择。隔离时以版本目录作为游戏目录，否则使用游戏根目录；assets、libraries、runtime 共享。整合包始终使用自己的实例目录。切换隔离策略不迁移已有存档、模组或设置。

### 模组管理

每张卡片左侧提供多选框；勾选后在搜索框下方一行的左侧显示批量更新、启用、禁用和删除图标及“全选”，同一行右侧依次是状态筛选、从文件安装和下载模组。全选仅作用于当前筛选结果，隐藏的项目自动取消勾选。批量更新只处理有更新的所选项目，悬停列出对应目标版本；启停跳过已处于目标状态的文件。批量删除统一确认后移入回收站，单项失败继续其余文件并汇总错误。

模组管理读取实际游戏目录直属的 `.jar` 和 `.jar.disabled`，支持按模组名或文件名搜索、全部/已启用/已禁用筛选。通过 SHA-1 批量匹配 Modrinth，仅将项目名称、简介和图标用于卡片；未知文件以文件名显示，网络失败仍可管理本地文件。卡片不显示统计、版本标签或说明副标题，详情、启停、位置、删除均使用带悬停提示和无障碍名称的图标。

加载摘要后检查与当前 Minecraft 版本和加载器匹配的较新正式发布；没有更新或尚未确认更新时隐藏更新图标，有更新时悬停显示目标版本号。更新先下载、校验，再复核旧文件和游戏运行状态后替换，保持原启停状态；失败或同名冲突保留旧文件。仅更新所选模组，不自动升级或安装依赖。离开分类会取消在途更新；更新在当前页显示进度，不进入下载任务页。

启停通过增删 `.disabled` 后缀实现，禁用模组名称显示删除线，名称与图标同时淡化，图标中央显示横线；启用后恢复正常；单项与批量启停仅更新变化的卡片，保留已有摘要、选择和滚动位置，不重新扫描或发起网络请求。加载中的摘要与更新结果合并时保留已修改的启停状态；不再符合当前筛选的卡片会移出列表。删除确认后移入回收站；文件位置打开资源管理器并选中文件。“从文件安装”使用原生 JAR 选择器，验证归档和加载器后复制到当前版本，不覆盖不同内容的同名文件；本地游戏版本范围与依赖仍需用户核对。“下载模组”直接进入下载页的模组分类。游戏运行或安装中拒绝修改；未隔离时这些操作影响共用同一 mods 目录的版本。

已被 Modrinth 识别的模组详情弹窗提供“Modrinth 主页”和“下载”：前者用系统浏览器打开项目主页，后者携带当前 Minecraft 版本及加载器，直接进入对应项目下载详情的文件列表，无匹配文件时显示空列表，不替换为其他版本或加载器。未识别文件不显示这两个入口。

## 下载与安装任务

游戏、模组、资源及 Java 安装复用独立下载任务页。创建任务后可离开页面；支持进度、暂停/继续、失败重试和取消。完成或取消清理结束后删除的是任务记录，不删除已发布文件或共享资源。

任务捕获创建时的目录与配置，传输共用并发、连接和速率预算，活跃批次沿用原限制。版本列表源与文件源分别设置，支持镜像优先、官方缓慢回退和官方优先。游戏使用 BMCLAPI，Modrinth 资源使用 MCIM，自定义链接不改写，认证不走镜像。

文件先写临时文件，校验后发布，同名冲突不静默覆盖。游戏和整合包完成暂存区安装后发布新版本，同一游戏目录的安装任务保护共享处理器输出。暂停复用已完成且有效的文件，未完成的单文件可能重新下载；取消不删除已成功下载的共享资源。关闭应用拒绝新任务并等待在途任务清理。

公共下载跨批次复用连接池，同时保留批次取消与预算。连接复用减少反复建连，但不能保证消除系统或代理端口耗尽。参数由 [DownloadHttpClient](../src/NyxLauncher/Services/DownloadHttpClient.cs) 维护。

## 内存与高级启动

全局设置 → 启动和版本详情 → 游戏设置共用内存与高级卡片。版本默认继承全局，修改后保存完整局部偏好，后续全局修改不覆盖它；游戏设置顶部独占一行、靠右的“恢复全局设置”按钮同时清除内存和高级启动的版本覆盖，之后持续跟随全局，直到再次手动修改版本设置。配置损坏或写入失败保留原值。

内存支持自动估算和手动分配。估算考虑游戏版本、加载器、实际模组目录及实时内存，公式由 [MemorySettings](../src/NyxLauncher/Services/MemorySettings.cs) 维护。界面预览不替代启动时计算，手动值不会因空闲内存下降而自动缩小，JVM 堆外仍会占用额外内存。

高级设置支持 JVM/游戏参数、GC、兼容组件开关与高性能 GPU 偏好。参数格式或 GC 冲突会报错，用户参数可能改变内存行为或导致启动失败。GPU 偏好写入当前用户针对实际 Java 路径的 Windows 设置，不保证硬件最终选择。组件条件与许可见[启动组件](launch-components.md)。

全局内存和高级配置分别为用户数据目录中的 `launch-memory.json`、`launch-advanced.json`；版本覆盖为版本目录中的 `nyx-memory.json`、`nyx-launch.json`，随版本改名和删除，不随隔离策略迁移。Java 规则见[Java 管理](java-management.md)，账户与日志规则见[账户与启动](accounts-and-launch.md)。

## 外观与背景

设置 → 通用提供外观、主题色和背景图片。默认跟随系统并保留绿色；WinUI 经典蓝使用 #0078D4 浅色主色。自定义配色把色调、主色和副色显示为三行全宽设置：左侧为名称，右侧为当前颜色的圆角色块；点击整行打开取色器，拖动时界面立即预览，关闭取色器后保存当前明暗组的颜色，另一组保持不变。色调影响背景与浅色块，主色用于主要操作，副色用于强调文字、图标和进度；浅色 WinUI 经典蓝预设使用白色按钮文字；自定义及其他配色按主色自动选择黑色或白色。

外观保存在 `%LOCALAPPDATA%/NyxLauncher/theme.json`，切换即时生效且不重建业务页面。损坏配置保持原文件并显示错误。背景支持 PNG、JPEG、BMP，限制为 32 MiB、边长 8192 像素和总像素 3200 万；解码校验后复制到配置目录，原图移动不影响背景。背景图片的不透明度可调整为 0–100%，不影响控件与文字。侧栏背景不透明度独立调整为 0–100%，默认以 45% 的主题底色遮罩进一步压低图片对比，收起和展开均生效，不改变文字与图标透明度。启用背景图片时卡片保留 88% 的主题底色，下载列表的普通、悬停和按下状态共用该底色与圆角。移除或更换后仅清理应用拥有的背景副本。图片丢失或无法加载时回退纯色并在外观设置报告错误。窗口标题栏、任务栏和可执行文件使用提供的 Nyx Logo。

背景图片上的标题栏、文件夹路径、导航文字和图标按所在区域的实际亮度自动选择黑字或白字。文字坐标映射到图片的实际绘制范围，避免宽图溢出窗口布局槽时重复裁切；取样图最长边为 1024 像素，局部使用亮度中位颜色，减少细小纹理与亮斑、暗斑的干扰。计算包含图片不透明度和侧栏遮罩，并在滚动、窗口大小或布局变化后重新采样。分类标签的悬停、按下和选中动画沿用自适应文字颜色，禁用或移除背景后恢复原有主题状态。卡片和实色按钮保留自身主题配色。文本输入选区及输入框聚焦边框跟随当前主色，包括可编辑版本筛选框，不使用系统强调色残留，不新增开关。

原生文本输入选区使用白字，因此主色过亮时选区底色使用同色相的深色版本，避免深色主题的浅绿选区上白字不可读；普通按钮和聚焦边框仍保留当前主色。
